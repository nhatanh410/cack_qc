## 4. Test levels & types

- **Level:** System testing (black-box, trên TestFlight) — QC không có quyền vào code.
- **Functional:** CRUD tuỳ biến ô, state banner/update, navigation Guide.
- **Non-functional:** Usability (hit-target), Accessibility (Dynamic Type), Localization, Compatibility (iOS 26 vs ≤25, iPhone vs iPad).
- **Change-related (regression):** 2699 automated test pass (trừ 3 fail cũ) chỉ là baseline — vẫn cần regression thủ công vì automated không cover visual (kính, crop ảnh, landscape).

## 5. Kỹ thuật thiết kế test case

- **Equivalence Partitioning:** tên ô = {rỗng, toàn space, string hợp lệ, string rất dài} → phủ mục 1.7/1.8 của note.
- **Boundary Value Analysis:** độ dài tên ô sát giới hạn ký tự — **cần hỏi dev xem có giới hạn hay không** trước khi viết case.
- **Decision Table** (logic dễ vỡ nhất — mục 1.13/1.14 của note):

  | Đã đổi tên? | Đã đổi màu? | Đổi ngôn ngữ máy | Kỳ vọng tên hiển thị |
  |---|---|---|---|
  | Y | – | Y | Giữ tên user đặt |
  | N | Y | Y | Dịch theo ngôn ngữ mới (chỉ màu là custom) |
  | N | N | Y | Dịch theo ngôn ngữ mới |
  | Y | Y | Y | Giữ tên user, giữ màu user |

- **State Transition Testing:**
  - Ô matrix: `default → customized → reset → default` (mục 1.9–1.11)
  - Banner/Update: `no-matrix-wallpaper → matrix-applied → switched-away` (mục 2.1–2.5)
  - Header pill: `non-pro (viên thuốc ghép) → pro (bánh răng đơn)` (mục 3.2/3.3)
- **Exploratory testing** (session-based, time-boxed): landscape iPad — ảnh landscape iPad **đầu tiên** trong bộ, chưa có checklist chính thức nào cover → cần charter riêng thay vì chỉ scripted test. Phạm vi đã thu hẹp (2026-09-09): chỉ khám phá **layout** (mục 1–2, dùng chung component), không cần lặp lại hành vi.
